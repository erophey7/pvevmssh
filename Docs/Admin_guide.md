## Установка

> В будущем планируется скрипт автоматической установки и обновления.

### Зависимости

- **Python 3.14+**

### Рекомендуемый путь установки

- `/opt/pvevmssh`

### Python и виртуальное окружение

Рекомендуется использовать `venv`:

```bash
git clone https://github.com/erophey7/pvevmssh.git
cd pvevmssh
python -m venv venv
source venv/bin/activate
pip install -r requirements.txt
```

Дополнительно можно собрать `liboqs` из исходников. Это необходимо для работы **постквантовых алгоритмов обмена ключами** (повышение безопасности при установлении соединения).

### Сборка liboqs из исходников (опционально)

#### Зависимости для сборки

**Ubuntu/Debian:**
```bash
sudo apt install build-essential astyle cmake gcc ninja-build libssl-dev unzip xsltproc doxygen graphviz valgrind
```

**Arch Linux:**
```bash
sudo pacman -Syu base-devel astyle cmake ninja openssl unzip libxslt doxygen graphviz valgrind
```

**Python (в отдельном venv для сборки):**
```bash
pip install pytest pytest-xdist pyyaml
```

#### Процесс сборки

Чтобы не засорять систему, выполняйте сборку в `.data/build_liboqs` с отдельным виртуальным окружением.

В качестве ветки используйте тег последнего релиза. На момент 09.04.2026 это `0.15.0`.

```bash
# Из корневой директории установки
mkdir -p .data/build_liboqs
cd .data/build_liboqs
python -m venv build_venv
source build_venv/bin/activate
pip install pytest pytest-xdist pyyaml
git clone https://github.com/open-quantum-safe/liboqs -b 0.15.0
cd liboqs
mkdir build && cd build
cmake -GNinja \
  -DCMAKE_BUILD_TYPE=Release \
  -DCMAKE_INSTALL_PREFIX=../../../liboqs \
  -DBUILD_SHARED_LIBS=ON \
  ..
ninja -j $(nproc --all)

# Можно протестировать библиотеку: ninja run_tests
# Падение теста tests/test_code_conventions.py::test_style на работу не влияет

mkdir -p ../../../liboqs
ninja install
cd ../../..
rm -rf build_liboqs
```

> На будущее можно сразу добавить директорию `.data/liboqs/lib` в переменную окружения `LD_LIBRARY_PATH`, но это не обязательно.

## Конфигурация

Конфигурация представляет собой JSON-файл по пути `.data/config.json`. Файл создаётся автоматически при первом запуске.

### Структура конфигурации

Конфиг разделён на следующие секции:

| Секция | Описание |
|--------|----------|
| `ssh` | Параметры SSH-сервера |
| `logger` | Настройка логирования |
| `db` | Настройки базы данных |
| `auth` | Параметры аутентификации |
| `pve` | Конфигурация PVE API и нод |
| `env` | Предустанавливаемые переменные окружения |
| `groups` | Группы пользователей и их права |

### Раздел `ssh`

| Поле | Описание |
|------|----------|
| `bind` | Адрес и порт для прослушивания (`host:port`) |
| `host_key` | Путь к приватному ключу сервера |
| `liboqs_custom_prefix` | Включение использования `liboqs_prefix` |
| `liboqs_prefix` | Префикс установки liboqs (если библиотека не в системных путях) |

### Раздел `logger`

| Поле | Описание |
|------|----------|
| `level` | Уровень логирования: `DEBUG`, `INFO`, `WARNING`, `ERROR` |
| `log_files` | Включение/отключение записи логов в файлы |
| `log_dir` | Директория для хранения логов |

### Раздел `db`

| Поле | Описание |
|------|----------|
| `type` | Тип БД: `sqlite`, `mariadb`, `mysql` (алиас на `mariadb`) |
| `masterkey_file` | Мастер-ключ для шифрования `api_secret` |
| `limits` | Лимиты для полей (см. ниже) |

**SQLite-only:**

| Поле | Описание |
|------|----------|
| `file` | Путь к файлу SQLite БД |

**MariaDB/MySQL-only:**

| Поле | Описание |
|------|----------|
| `host` | IP-адрес сервера БД |
| `user` | Пользователь БД |
| `password` | Пароль |
| `database` | Название базы данных |
| `port` | Порт сервера |

#### Лимиты (`limits`)

| Поле | Описание |
|------|----------|
| `env` | Максимальное количество записей в `saved_env` |
| `history` | Максимальное количество записей в истории команд |

### Раздел `auth`

| Поле | Описание |
|------|----------|
| `ssh_key_enabled` | Включена ли аутентификация по SSH-ключу |
| `password_enabled` | Включена ли аутентификация по токену |
| `default_group` | Группа по умолчанию для новых пользователей |
| `force_group` | Список пользователей с принудительной группой в формате `{"username": group_id}` |
| `limited_inheritance` | Ограничение наследования прав групп. Без этого группа может получать вложенные права от других групп |

### Раздел `pve`

| Поле | Описание |
|------|----------|
| `main_node_host` | URL главной ноды кластера Proxmox VE |
| `ssl_verify` | Проверка SSL-сертификата (`true` / `false`) |
| `timeout` | Таймаут HTTP-запросов к API (в секундах) |

### Раздел `env`

Содержит предустанавливаемые переменные окружения в формате ключ-значение.

### Раздел `groups`

Содержит список групп пользователей.

#### Пример группы

```json
"0": {
  "name": "Administrator",
  "permissions": ["admin_permission"],
  "permset": [1, 2, 3]
}
```

| Поле | Описание |
|------|----------|
| `"0"` | ID группы |
| `name` | Имя группы |
| `permissions` | Список прав группы |
| `permset` | ID групп, права которых наследуются |

## Права и группы

### Список прав

#### Административные права

| Право | Описание |
|-------|----------|
| `admin_permission` | Полный доступ администратора |
| `db_admin` | Право администратора БД (изменение пользователей, просмотр секретов) |

#### Расширенные пользовательские права

| Право | Описание |
|-------|----------|
| `poweruser_permission` | Расширенные права пользователя |
| `db_viewer` | Право инспектора БД (просмотр всех записей, кроме секретов) |
| `system_permission` | Доступ к системным ресурсам (bash и др.) |

#### Права обычного пользователя

| Право | Описание |
|-------|----------|
| `user_permission` | Базовые права пользователя |

#### Права тестировщика

| Право | Описание |
|-------|----------|
| `tester_permission` | Доступ к отладочным командам |
